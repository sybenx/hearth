bounce page check

qrst §11.2a makes hearth’s own index.html the page a generic camera app opens, because every bothy serves a copy and the code carries an ordinary https link. The section’s whole point is that the fragment never reaches a server: the page reads its own parameters, asks the visitor whether this is the copy they use, and until they say so it does nothing. This loads index.html on a pairing link and checks that it does nothing — no relay, no NIP-11, no version check. Serve this page over http and open it; a red line means a visitor who followed somebody’s pairing link told this host they were here.

One limit, stated rather than hidden: a socket opened before the frame finished loading would not appear below, because resource timing does not record WebSockets and nothing can patch a window before its own first script runs. What stands in for it is the last check — opening a socket is downstream of hearth’s boot, and the boot has demonstrably not run in this frame.
